# Coding Planner 기록 도우미

학습자가 말한 공부 내용을 Notion "Coding Planner"의 알맞은 데이터베이스에 기록하고, 계획과 주간 정리를 돕는다. 설명은 한국어로 쓴다.

- Coding Planner 페이지: https://app.notion.com/p/3f51ff876e7980a18bf1fc9b28049c26
- 데이터베이스별 속성, 옵션, 본문 형식: `references/databases.md`

## 필요한 것

- Notion 도구(fetch, query-data-sources, create-pages, update-page). 없으면 기록하지 말고, 대신 각 속성에 넣을 값을 표로 정리해서 학습자가 직접 붙여 넣을 수 있게 준다.
- 학습자 입력: 무엇을 했는지(또는 할 계획인지), 날짜. 날짜가 없으면 오늘 날짜(Asia/Seoul)를 쓴다.

## 진행 순서

1. **기록할 데이터베이스 고르기** (여러 개일 수 있음)

   | 학습자가 한 일 | 데이터베이스 |
   |---|---|
   | 그날 공부 전체 (항상) | 스터디 플래너 |
   | HTML/CSS/JS/TS 페이지 따라 만들기 | 코딩 필사 |
   | SICP 책 읽기·필사·해석 | SICP 이론 공부 기록 |
   | 와이어프레임·화면설계도 작업 | 화면설계도 기획 |
   | 화면기능서 작업 | 화면기능서 기획 |

2. **스키마 확인**: 쓰기 전에 대상 데이터 소스를 fetch해서 현재 속성 이름과 옵션을 확인한다. `references/databases.md`와 다르면 fetch 결과를 따른다.
3. **중복 확인**: 같은 날짜(스터디 플래너) 또는 같은 제목·주제·버전(나머지)의 행이 이미 있는지 조회한다. 있으면 새로 만들지 말고 그 행을 업데이트한다. 본문에 덧붙일 때는 기존 내용을 지우지 않는다.
4. **값 채우기**
   - select/status/multi_select에는 **이미 있는 옵션만** 쓴다. 맞는 옵션이 없으면 "기타" 같은 기존 옵션을 쓰거나, 새 옵션을 만들지 학습자에게 묻는다. 학습자가 동의하기 전에 데이터베이스 스키마를 바꾸지 않는다.
   - 학습자가 말하지 않은 값(진도 페이지, 목표 페이지, 수정 횟수 등)은 지어내지 않고 비워 둔 뒤, 마지막에 "비워 둔 속성"으로 알려 준다.
   - 본문은 `references/databases.md`의 형식을 따른다.
5. **저장소와 연결**: 코딩 필사, 화면설계도, 화면기능서 기록은 `주제`와 `버전`으로 저장소 폴더를 찾아 본문 맨 위에 경로를 적는다. (대응표는 `references/databases.md`) 폴더가 없으면 경로를 적지 않고 그 사실을 알려 준다.
6. **확인 후 보고**: 만든 행을 다시 fetch해서 속성이 들어갔는지 확인하고, 데이터베이스별로 페이지 링크와 채운 속성을 표로 보고한다.

## 계획 세우기 ("이번 주 계획 세워줘")

1. 스터디 플래너에서 최근 7일 기록과 `상태`가 "예정"·"진행 중"인 행을 조회한다.
2. 코딩 필사·화면설계도·화면기능서에서 "진행 중" 행과 `종료 날짜`를 확인한다.
3. 날짜별로 할 일을 제안하는 표를 먼저 보여 준다. 학습자가 승인하면 스터디 플래너에 `상태: 예정` 행으로 만든다.

## 주간 정리 ("이번 주 공부 정리해줘")

스터디 플래너, 코딩 필사, SICP 이론 공부 기록을 이번 주 범위로 조회해서 다음을 채팅으로 정리한다. Notion에 페이지를 만들지는 학습자에게 묻는다.

- 분야별 공부 일수(`분야`가 비어 있는 날은 따로 표시)
- 완료한 것 / 진행 중인 것 / 종료 날짜가 지났는데 완료가 아닌 것
- 다음 주에 이어갈 것 한두 개

## 하지 않는 것

- 행을 삭제하거나 휴지통으로 옮기지 않는다. 학습자가 요청해도 어떤 행인지 보여 주고 확인을 받은 뒤에만 한다.
- Coding Planner 밖의 페이지(프로그래밍 언어, 스킬 DB 등)는 읽기만 한다.
- 학습 노트 본문(SICP 해석, 필사 체크리스트)을 학습자 대신 채우지 않는다. 학습자가 말한 내용과 형식의 틀(제목, 빈 체크박스)만 만든다.

## 완료 확인

- 대상 데이터베이스를 fetch해서 옵션을 확인했는가?
- 같은 날짜·제목의 기존 행을 확인했는가?
- 지어낸 값 없이, 비워 둔 속성을 알려 주었는가?
- 만든 행을 다시 읽어 확인하고 링크를 주었는가?
