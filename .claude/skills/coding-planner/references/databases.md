# Coding Planner 데이터베이스 (2026-10-16 기준)

쓰기 전에 항상 데이터 소스를 다시 fetch해서 이 내용과 같은지 확인한다. 날짜 속성은 `date:<속성>:start`, `date:<속성>:is_datetime`(날짜만이면 0)으로 넣는다.

## 1. 스터디 플래너 — 하루 공부 로그

- 데이터 소스: `collection://3fa1ff87-6e79-8095-a104-000b907f4909`

| 속성 | 형식 | 값 |
|---|---|---|
| 스터디 내용 (제목) | title | `YYYYMMDD(요일)` 예: `20261015(목요일)` |
| 공부 날짜 | date | 그날 날짜 |
| 분야 | multi_select | 코딩 필사, SICP, 설계 원칙, 코딩 테스트, 기타 |
| 상태 | status | 예정, 진행 중, 완료 |
| 공부 시간(분) | number | 학습자가 말한 경우만 |
| 메모 | text | 짧은 한 줄 (할 일, 기다리는 일 등) |

하루에 한 행. 같은 날짜 행이 있으면 `분야`를 합치고 `메모`는 기존 내용 뒤에 ` / `로 이어 붙인다.

## 2. 코딩 필사 — 페이지 따라 만들기

- 데이터 소스: `collection://3f91ff87-6e79-8047-9e6b-000b9e3a8dc0`

| 속성 | 형식 | 값 |
|---|---|---|
| 제목 | title | 예: `오늘의 정원 코딩 필사` |
| 주제 | select | 로그인 페이지, 회원가입 페이지, 장바구니 페이지, 베스트 상품 페이지, 게시판 페이지, 마이페이지, 이벤트 페이지 |
| 버전 | select | v1.0, v2.0, v3.0 |
| 프로그래밍 언어 | multi_select | HTML, CSS, 자바스크립트, 타입스크립트, JSONC, JSON |
| 상태 | status | 시작 전, 진행 중, 완료 |
| 공부일 | date | 그날 날짜 |
| 작업 날짜 | date | 작업 시작일 |
| 종료 날짜 | date | 목표 종료일 |

본문 형식 (기존 "오늘의 정원 코딩 필사" 페이지 기준):

```
저장소: 03-genspark-study/01-web/projects/<폴더>/<버전>/

# HTML
## `<body>` 태그 작업 확인 순서
- `<태그>` 태그
	- [ ] `class="..."` 작성 및 확인
---
# CSS
- [ ] `:root { ··· }`
- [ ] 전역 초기화(Global Reset)
---
# script.ts
- `<태그>` 태그
	- [ ] id="..."
```

체크박스에 HTML ↔ CSS ↔ JS 연결이 끊긴 항목이 있으면 학습자가 쓴 방식대로 `→ CSS 변수에 없음`, `→ script.ts에 없음`처럼 이유를 화살표로 붙인다.

## 3. SICP 이론 공부 기록

- 데이터 소스: `collection://3f71ff87-6e79-8025-9bcb-000b1ac6166f`

| 속성 | 형식 | 값 |
|---|---|---|
| 제목 | title | 공부한 주제, 예: `재귀 함수 이론` |
| 공부일 | date | 그날 날짜 |
| 진도 페이지 | text | 책 쪽수, 예: `107 페이지` |
| 목표 페이지 | text | 그날 목표, 예: `5 페이지 필사` |

본문 형식 (기존 "재귀 함수 이론" 페이지 기준): 소제목(`# 페르마 판정법`, `# 105 페이지`) → 책 코드 블록 → `## 수정 해석` 불릿 → 필요하면 `## 올바른 … 구조`로 if-else 변환 코드. 해석 내용은 학습자가 쓴다. 개념 질문이 섞여 있으면 sicp-js 스킬로 넘긴다.

## 4. 화면설계도 기획 / 5. 화면기능서 기획

- 화면설계도 기획: `collection://3f71ff87-6e79-8064-982e-000bbc8d7d1e`
- 화면기능서 기획: `collection://3f71ff87-6e79-800c-aad7-000b8bb625ad`

두 데이터베이스의 속성은 같다.

| 속성 | 형식 | 값 |
|---|---|---|
| 제목 | title | `화면설계도` 또는 `화면기능서` |
| 주제 | select | 로그인 페이지, 회원가입 페이지, 마이페이지, 장바구니 페이지, 공지사항 페이지, 베스트 상품 페이지 |
| 기본 버전 | select | v1.0, v2.0, v3.0 |
| 수정 버전 | select | v1.1~v1.3, v2.1~v2.3, v3.1~v3.3 |
| 수정 횟수 | select | 1회~10회 |
| 상태 | status | 시작 전, 진행 중, 완료 |
| 작업 날짜 / 종료 날짜 | date | |

- `수정 버전`은 `기본 버전`과 같은 계열이어야 한다. (v1.0 → v1.1~v1.3) 계열이 맞지 않으면 학습자에게 확인한다.
- 수정을 기록할 때는 기존 행의 `수정 횟수`를 한 단계 올린다. 10회를 넘거나 v○.3 다음 버전이 필요하면 옵션이 없으므로 학습자에게 묻는다.
- 본문은 시안 이미지 또는 하위 페이지(`login-wf-01-design-r1.png` 형식). 이미지 업로드는 학습자가 직접 한다.
- "게시판 페이지", "이벤트 페이지"는 이 두 데이터베이스에 옵션이 없고, "공지사항 페이지"는 코딩 필사에 없다.
