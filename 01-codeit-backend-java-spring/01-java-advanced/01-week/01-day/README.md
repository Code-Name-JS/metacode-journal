## 새롭게 이해한 개념

메소드는 하나의 자바의 프로그래밍 언어 문법으로 구성 요소가 언제, 어디서, 어떤 값을 받아 어떻게 실행되고 무엇을 반환하는지 결정해 줍니다. 저는 자바를 배우면서 자바의 목표가 "모든 전자기기에서 돌아가는 프로그래밍 언어를 만들자!라는 의도에서 프로그래밍 언어가 정해진 문법과 규칙을 따른다는 점을 이해하게 되었습니다. 새로운 부분은 어떤 코드를 작성하든 반드시 기본 구조가 있고 구조는 문법과 규칙에 의해 꼭 지켜져야 하는 이유를 자바 프로그래밍 언어는 설명해줍니다.

특히 자바의 구조는 3가지로 구성되는데 타입 선언부와 코드의 이름, 바디로 설정됩니다. 타입 선언부는 클래스이고 이름은 파스칼 표기법을 따릅니다. 또한 바디는 클래스를 설정하는 동작에 대한 정의입니다.

클래스 바디에서는 다양한 요소를 정의할 수 있는데 프로그램을 어디서부터 시작할지 알려주는 특별한 코드가 main메소드로 처음 자바의 프로그램을 시작하는 시작점이 됩니다.

즉, 메소드는 언제, 어디서, 어떤 값을 받아서 어떻게 실행되고 무엇을 반환하는 과정속에서 자바의 기본 구조를 가지고 있다는 것입니다.

---

## 실습 내용(문제 풀이 과정)

```
class Solution {
    public int solution(int num1, int num2) {
        if (num1 == num2) {
            return 1;
        } else if (num1 != num2) {
            return -1;
        }

        return 0;
    }
}
```

문제 풀이에서 Solution을 사용하면서 모든 실행 경로에 int 값을 반환해야한다는 중요한 내용을 알게 되었습니다. 저는 반환이라는 단어를 return으로 이해하였고 class Solution이 public int solution이 되었을 때 int num1과 int num2를 속성값으로 가지고 있었습니다. 이때 if문 조건문으로 else if까지 작성했는데 마지막에 return 작업이 모두 if문과 else if문에 작성되어 있어 return 0;을 꼭 작성해야하는지 몰랐습니다. 그래서 Solution을 사용하면 모든 실행 경로에서 int값을 반환해야 하기 때문에 실행이 끝난 후 또 한번 반환의 조건을 갖춰야 int값을 정확하게 반환시키는 것으로 이해했습니다.

```
class Solution { 
    public int solution(int num1, int num2) { 
        if (num1 == num2) { 
            return 1; 
        }

        return -1;
    } 
}
```
하지만 else if문은 조건에서 서로 반대되는 연산자를 가짐으로 두 값이 같거나 다르거나 둘 중 하나이면 첫 번째 if가 거짓이 될 때 두 번쨰 조건은 항상 참이 됩니다. 그래서 불필요하고, return을 만나면 메소드가 즉시 종료되기 때문에 else도 생략할 수 있다는 것을 이해하게 되었습니다.

## 어려웠던 부분

메소드가 언제, 어디서, 어떤 값을 받아 실행되고 무엇을 반환하는 과정이 자바의 기본 구조로 이루어졌다는게 어려웠습니다. 

즉, 어떤 정보를 가지고 동작하는지 한 문장으로 요약하는 구조가 자바 스프링 부트와 연동되면서 터미널의 호출 및 실행 방식에서 Java의 명명 규칙이 Spring Boot와 연동되기 위해서는 파스칼 표기법과 어노테이션이 Spring의 기능을 추가하여 웹 서버나 애플리케이션을 구성한다는 것을 알게 해주었습니다.

특히 자바의 3가지 구조 속에서 파스칼 표기법이 가장 어려웠는데 클래스를 학습하면서 객체에 관한 구체적인 속성과 행동을 정해진 문법과 규칙으로 구성해야 한다는 것이 다른 개념으로 번졌습니다. 그래서 필드와 메소드 차이를 알아야 했고, 생성자는 어떤 역할을 하고, 자동차를 예시로 이러한 내용을 통해 정의할 수 있는지 알아보는 작업이 필요한 것 같았습니다.

아직 자바를 입문한지 4일 된 초보자라서 정해진 문법과 규칙을 이해하는데 자바 프로그래밍 언어를 필사하는 방식에서 한정적이고 제한된 기초 문법에 국한되는 코드를 주로 작성하다보니 다른 문제를 풀 때 다양한 문법과 규칙을 준수하기 어려운 부분이 있다고 생각했습니다.

아마도 문법에 대해서 적응해야 스스로 코드를 작성하는 과정까지 가지 않을까 싶었습니다.
